# 蒜宝第一阶段实施计划

## 基线与现实约束

- 以当前 HEAD 中已确认的蒜宝原型和架构文档为实现基线，保留现有工作区中与本任务无关的 `docs/README.md` 删除及 `.zcode/` 内容，不回退、不覆盖。
- 当前移动端没有版本化的 `capacitor.config.*`、`ios/`、`android/` 工程，`cap sync` 在干净检出上不可用。因此本轮会完成共享/网页/Electron 功能，并落地移动能力接口、WebView 内体验、通知/定位适配代码；原生工程和系统日历插件只有在仓库具备可复现移动工程后才能完成真机接线。不会把未验证能力标记为完成。
- 系统日历在 Desktop/Web 明确降级为本地日程；移动端先提供只读接口和 unavailable adapter。若没有经 Capacitor 7 真机验证的维护良好插件，不引入宽权限第三方插件冒充完成，而把窄原生插件列为剩余阻断项。
- 完整一期按可验证批次连续推进，不采用一个不可回滚的大提交。

## 批次 1：修正原型并建立领域契约

1. 新增 `src/shared/types/suanbao.ts`，定义可序列化的偏好、Placement、Command、Operation、Activity、确认卡、待办、提醒、番茄、日程、天气、能力和受控路由类型。
2. 为跨窗口 payload 增加 runtime 校验及长度、ID、坐标边界测试。
3. 拆分 `SuanbaoPet` 为视觉、气泡、确认卡、手势控制器和应用内 Host；保留当前 CSS 形象作为素材 fallback。
4. 用纯手势状态机修复单击/双击/拖拽竞态和旧位置快照，显式实现 animation-off、键盘和 aria-live。
5. 从页面白名单改为默认全业务页面显示，确保图片生成页出现；仅设置弹窗和显式敏感页面隐藏。
6. 新用户默认关闭；已有 V1 偏好保持原选择，hydration 完成前不闪现。

## 批次 2：独立蒜宝会话、Activity 与本地意图

1. 在 `src/renderer/packages/suanbao/` 建立 Domain 与 Application Services。
2. 复用现有 `createModel()`、`ModelInterface.chatStream()` 和模型配置，但不创建普通 Session；建立独立短记忆 repository。
3. 以 operation ID 和 AbortController registry 管理流式执行与取消，不再从 `Message.cancel` 推断。
4. 建立序列化 Activity/ViewModel，覆盖对话、确认、提醒、番茄和错误状态；应用内与独立窗口消费同一 ViewModel。
5. 实现气泡短答、复杂结果的受控“在 KOD 中展开”，并保证普通聊天列表不被污染。
6. 实现本地意图解析：待办、提醒、番茄、显隐/锁定和 KOD 导航；模型失败时使用本地规则及固定台词。
7. 所有副作用走 `draft -> awaiting-confirmation -> execute`，使用幂等键防止重复创建。

## 批次 3：统一存储与实用助手闭环

1. 建立一个按账户隔离的 `SuanbaoRepository`，而不是给 Platform 增加多组碎片 getter。
2. Desktop/Web 使用现有 IndexedDB/Platform Storage；Mobile 增加 SQLite adapter；Test 使用内存实现。
3. V1 裸 localStorage 只在专项迁移器中读取，写入 V2 成功后再删除旧值；偏好、设备位置和业务实体分层存储。
4. 完成待办 CRUD、提醒 CRUD、番茄状态机和本地日程 CRUD。
5. 使用绝对时间、时区、幂等 delivery 状态实现重启恢复、过期补偿和重复规则；测试 DST、账户切换和重复确认。
6. 设置页增加显示、活跃模式、声音、锁定、勿扰、通知、天气、日历、清空记忆和删除本机数据。

## 批次 4：天气、通知、定位和日历能力

1. 在 Platform 上增加聚合的 Suanbao system capability，不通过 `platform.type` 猜能力；后台保证使用 `reliable | foreground-only | unavailable`。
2. 天气接 Open-Meteo Geocoding/Forecast，支持手动城市、15/60 分钟 TTL、最后成功数据和离线降级；模型不得虚构天气。
3. Web 使用 Geolocation/Web Notification；提醒明确为页面存活保证，重开后补偿，多标签页避免重复。
4. Desktop 通知和可靠调度放 Electron 主进程。
5. Mobile 增加与 Capacitor 7 对齐的 Local Notifications、Geolocation adapter 和冷/热启动通知导航代码；若原生工程仍缺失，报告接线与真机验证未完成。
6. 本地日程全平台可写；系统日历接口只读。Desktop/Web 返回 unavailable；移动在窄插件真机验证前也保持 unavailable，不请求 WRITE_CALENDAR。

## 批次 5：Electron 生命周期、安全 broker 与独立窗口

1. 先修主窗口生命周期：增加真正退出标志；普通关闭隐藏到托盘并保留 renderer；托盘退出、更新和重启走统一真正退出路径；拆分确定性的 show/hide/toggle。
2. 修复 `kod://` 冷启动与旧 `chatbox://` 残留，通知和蒜宝导航只接受受控 route ID。
3. 在 `src/main/suanbao/` 建立 window manager、broker、IPC handlers、scheduler 和 tray integration。
4. 主 renderer 作为一期 AI 业务宿主；main broker 只做 sender 身份验证、schema 校验、ready/bootstrap、转发、超时和断线恢复，不承载 AI 业务。
5. 新增独立最小 preload，只暴露命名 API；绝不复用主 preload 的通用 `invoke`，宠物窗口无文件、Shell、Sandbox、MCP 或凭据权限。
6. 配置 electron-vite 多 preload/renderer 入口，新增最小蒜宝 renderer，不加载主 Router 和完整应用。
7. 创建透明、无框、置顶、skipTaskbar 的窗口；按交互状态切换点击穿透和焦点；支持多显示器、DPI、显示器拔插和位置恢复。
8. 托盘扩展为打开 KOD、显示/隐藏蒜宝、暂停动画、勿扰、设置和退出。
9. Windows/macOS/X11 实现完整目标；Wayland 不支持的点击穿透/绝对位置标记 capability 降级。

## 批次 6：素材包与体验完善

1. 增加官方素材 manifest schema、loader 和校验测试；当前 CSS 蒜宝继续作为资源失败或减少动态效果 fallback。
2. 支持 `idle/listening/thinking/executing/success/error/reminding/focus/rest/sleeping` 状态、动作优先级、可打断规则和 hit regions。
3. 完成摸头/身体互动、活跃模式随机动作、冷却、勿扰和无声默认。
4. 文档化设计期 AI 生图命令输入输出、审核元数据和资源目录；不在运行时生图。

## 批次 7：验证与诚实收口

1. 每个批次运行相关 Vitest；最终运行 `pnpm run check`、蒜宝测试、相关集成测试和 `pnpm run build`。
2. 增加 shared schema、手势、Activity、意图、幂等、存储迁移、天气缓存、调度、权限降级、broker sender、window manager 和 preload surface 测试。
3. 添加 Electron 关键路径测试条件：关闭到托盘、真正退出、broker 重连、窗口显隐、通知点击、多显示器；无法在当前环境执行的 macOS/Linux 真机项明确列出。
4. 检查移动构建链路；若仍因缺少原生工程阻断，给出确切失败命令和所需工程资产，不宣称 iOS/Android 原生通知/日历完成。
5. 执行 `git diff --check`，报告改动文件、通过/失败/跳过的测试和剩余平台阻断项。
6. 不提交、不推送，除非用户另行要求。

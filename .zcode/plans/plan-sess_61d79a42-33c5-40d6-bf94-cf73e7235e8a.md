## 第一性原理结论

你的目标不是“合并 GitLab 分支”，而是：**保持当前工作区所有已提交和未提交功能不变，只复制目标分支最终版本中两个用户可见能力及其运行所必需的行为**。直接 cherry-pick 或整文件覆盖不符合目标，因为 `feat/select_url_sk` 同时包含验证码登录、dashboard、lockfile 重写、默认图片模型清空、超时参数等无关改动，并且目标分支本身含确定的类型/测试问题。

另一个必须指出的事实是：目标分支所谓“零售站/节点切换”并不只是两个下拉框。它依赖一整条业务链：节点占用与释放、全局持久化、模型读取、动态 provider、余额检查和发送日志。若只复制 UI，选择不会真正影响聊天请求。因此本次将移植这条**与两个切换功能直接相关的最小闭环**，但不复制无关功能。

## 实施方案

1. **保护当前工作区**
   - 以当前工作树为唯一编辑基线。
   - 不执行 `reset`、`checkout`、`restore`、整分支合并或 cherry-pick。
   - 不覆盖 Tinpay、深链、preload 等现有未提交工作；尤其保留 `src/renderer/packages/remote.ts` 当前导出和 `src/renderer/routes/settings/chatbox-ai.tsx` 的 `TinpayDemoCard`。

2. **移植目标分支最终版选择器**
   - 新增 `src/renderer/components/RelayStationSelector.tsx`。
   - 沿用目标分支的界面位置、中文文案、默认空选择、零售站列表、节点固定编号、空闲/占用状态、当前已选节点例外，以及 `kod_stations` 缓存行为。
   - 沿用接口：`/api/relay-station/list`、`/api/relay-station/{stationId}/keys` 和所选站点 `/models`。
   - 保持最终版受控组件语义，避免初版组件自己重复占用节点。
   - 只做不改变产品行为的质量修正：准确类型、移除未使用导入、避免旧请求覆盖新选择。

3. **实现全局同一节点的完整状态闭环**
   - 保留目标分支 `kod_relay` 的全局持久化名称和数据语义，使首页及所有会话共享同一选择。
   - 抽取一个共享 relay hook/module，统一执行：恢复选择、后端 balance 恢复、`select-key`、`release-key`、模型加载和动态 provider 更新，避免目标分支在首页/会话页复制两套不一致状态机。
   - 接口基址使用当前代码已有的 KOD API origin/config 来源；只有在当前来源与目标实际接口不兼容时，才保留目标的 localhost 行为。不会把同一个地址散落硬编码在多个页面。
   - 保留目标的全局选择结果和后端节点占用语义；选择零售站时释放原节点，选择节点时锁定新节点。
   - 首页和会话页统一处理业务 `409`，避免目标代码“首页锁定失败仍继续使用节点”的漏洞；显示目标文案“该会话的节点已被占用，请重新选择节点”。
   - 清空或登出时同步清除运行时 relay provider，避免旧 URL/API key 继续残留生效。

4. **动态模型/provider 与旧功能兼容**
   - 沿用目标 provider 标识 `__kod_relay_station__`、名称 `KOD AI`、OpenAI-compatible 类型，以及以 station URL/API key/models 驱动聊天请求的行为。
   - 在全局 settings 中增量注册/更新该 custom provider，不覆盖其他 provider，尤其不删除当前图片模型、Tinpay 或其他现有设置。
   - 选择清空时只清理该 relay provider。
   - 模型过滤同时校验 provider ID 和 model ID，确保只显示当前节点的模型，而不是其他 provider 的同名模型。
   - 给 `InputBox` 增加类型安全的 `modelFilter` 透传。
   - 禁止旧的自动 ChatboxAI relay 配置与手动节点选择竞争，但采取条件化/最小改动，不照搬目标分支“全面注销 ChatboxAI、清空图片默认模型和设置页模型管理”的破坏性做法。
   - 聊天默认值只在确有必要时改为未选择；保留当前图片默认 `OpenAI / gpt-image-1` 和上下文上限行为。

5. **沿用目标 UI 位置和发送相关行为**
   - 首页：登录后在新聊天 `InputBox` 上方显示选择器。
   - 会话页：登录后在 Header 下方、消息列表上方显示选择器。
   - 新增目标分支余额不足提示组件和文案。
   - relay provider 发送前调用 `/api/session/balance`；余额不足则阻止发送并显示提示。
   - relay 消息开始发送时调用 `/api/log/sync/start`。
   - 不移植 dashboard、邮箱验证码、设置页大规模删减、lockfile 重写、SDK 参数、超时和其他无关改动。

6. **持久化与安全边界**
   - 为了满足“沿用目标持久化行为”，仍使用 `kod_relay` 和 `kod_stations`。
   - 目标分支会将节点 API key 明文保存到 localStorage 和 provider settings，这是客观安全弱点；本次不会擅自改成只存 ID，因为那会改变离线恢复行为和需要新增服务端契约。
   - 但会限制重复副本，不把 key 写入额外日志、URL 或无关 store，并在释放/登出时尽可能清理。

7. **测试**
   - 为选择器纯逻辑补测试：节点编号、状态排序、占用禁用、当前节点例外。
   - 为共享 relay 状态/API 补测试：本地恢复、后端恢复、选择、释放、409、模型加载、清理。
   - 为动态 provider/model filter 补最小契约测试，确认不丢其他 provider。
   - 现有 Tinpay 和当前未提交文件不做与本功能无关的重构。

8. **验证**
   - 运行本次新增及直接相关 Vitest 测试。
   - 运行 `pnpm exec tsc --noEmit --incremental false`，避免额外写入增量缓存。
   - 对本次涉及文件运行 Biome lint/check，再运行仓库 `pnpm run lint`。
   - 如全量检查出现与本次无关的既有失败，只修复本次引入的问题，并把其他失败的文件、命令和输出如实列出。
   - 最后检查 `git diff`/`git status`，确认原有未提交文件未被覆盖、不包含目标分支无关改动。
   - 不创建 commit。

# Tinpay M1 Windows Electron 实施计划

## 范围与前提

本轮只实现 **Windows Electron 主链路**，入口放在当前活跃的 **KOD AI 设置页**。Chrome/Edge popup 暂不实现。

客户端不会直接调用 Tinpay，也不会持有 Tinpay M1 Bearer。由于本仓库不含 KOD 后端，本轮暂按以下建议 BFF 契约实现客户端；真实联调前由 KOD 后端确认或兼容：

- `POST {KOD_API_ORIGIN}/api/tinpay/demo-sessions`
- `GET {KOD_API_ORIGIN}/api/tinpay/demo-sessions/{sessionId}`
- 客户端使用现有 KOD 用户认证机制（`x-kod-access-token` 及已有刷新逻辑）
- KOD 后端负责：Tinpay Bearer、`sourceOrderId`、`userReference`、价格/币种、`preAuthPassed`、上游 `Idempotency-Key`、`callbackState`、`returnUrl` 和完整上游请求
- 客户端只提交产品意图与 Electron 上下文；如果后端实际契约不同，仅需替换集中式 API 适配层

在 KOD BFF 尚未上线或契约不兼容时，功能会明确显示创建失败，不能绕过安全边界直连 Tinpay。也无法在本仓库内诚实返回真实首次 POST 的 HTTP 状态、sessionId 或媒体授权结果；这些只能在 BFF 和测试凭证到位后通过打包联调产生。

## 1. 固化共享协议和运行时校验

新增 Tinpay 共享类型和严格 Zod Schema，覆盖：

- KOD BFF 创建意图和会话响应
- `sessionId`：`^tp_demo_[0-9a-f]{20}$`
- 完整状态枚举：`CREATED`、`READY`、`RECORDING`、`TRANSCRIBED`、`MATCHED`、`RETRY_REQUIRED`、`COMPLETED`、`CANCELLED`、`EXPIRED`、`ERROR`
- `demoOnly: true`
- 前端事件白名单：`tinpay.ready`、`tinpay.recording_started`、`tinpay.retry_required`、`tinpay.completed`、`tinpay.cancelled`、`tinpay.permission_denied`、`tinpay.error`
- 事件版本 `1.0`、session 绑定、ISO 时间戳及受限错误字段
- Electron 打开、关闭、外部浏览器降级和事件通知契约

新增集中式 IPC channel 常量，避免任意字符串 channel。

## 2. 新增 KOD BFF 客户端

在 renderer API 层新增独立 Tinpay 包装器：

- 使用 `getAuthenticatedAfetch()`，不读取或发送 Tinpay Bearer
- POST 仅提交建议契约，例如产品标识/场景和：
  - `platform: 'windows'`
  - `container: 'electron'`
  - `hostAppId: 'kod-electron'`
  - 当前应用版本
- 对 BFF 成功响应做严格 Schema 校验
- 查询精确 `sessionId`
- 创建 POST 关闭通用自动重试，防止在 BFF 幂等实现未确认时重复创建
- 保留并展示脱敏 `X-Request-Id`/服务端 request ID
- 不记录完整 `checkoutUrl`、opaque token、callbackState 或认证信息
- 支持 `AbortSignal`

API 路径集中定义，后端契约确定后可单点调整。

## 3. 实现 Tinpay 专用 Preload

新增独立 preload bundle，只向远程 Tinpay 页面暴露：

```ts
window.tinpayHost.postMessage(message): void
```

该 preload：

- 只向固定 `tinpay:event` channel 发送数据
- 不暴露通用 invoke、Node、文件、Shell、存储或 URL 打开能力
- 不返回宿主状态或凭证

同时在 electron-vite 配置中增加 Tinpay preload entry。

## 4. 实现独立安全 BrowserWindow

新增 `TinpayWindowManager`，参照现有 Suanbao 独立窗口模式，但加载经过验证的 Tinpay HTTPS 页面。

窗口配置：

- 约 `420 × 720`，最小 `360 × 640`，按屏幕工作区收敛
- `contextIsolation: true`
- `nodeIntegration: false`
- `sandbox: true`
- `webSecurity: true`
- `webviewTag: false`
- 生产禁用 DevTools
- 专用非默认 Session partition
- 使用专用 Tinpay preload

URL 安全策略集中为纯函数并用于初始加载、导航、重定向、popup、事件发送者校验和外部浏览器降级：

- 仅允许 `https://tinpay.kai.com`
- staging 仅在最终 DNS/TLS 验收并配置启用时允许
- 拒绝 HTTP、file、data、javascript、blob、自定义 Scheme、用户信息、异常端口和相似域名
- 禁止 `<webview>` 和子 Electron 窗口
- 外部浏览器只打开主进程保存并再次校验的原 checkoutUrl，不接受远程页面提交任意 URL

## 5. 媒体权限最小放行

只在 Tinpay 专用 Session 上注册 permission check/request handlers：

- 仅活动 Tinpay 主窗口、主 frame、精确 allowlist origin 可申请
- 仅允许摄像头和麦克风对应的 `media`
- 默认拒绝位置、通知、剪贴板、屏幕录制、USB、HID、Serial、Bluetooth、MIDI、文件系统等权限
- 权限拒绝通知主 Renderer，展示说明和同一 URL 外部浏览器降级
- 不修改 `session.defaultSession`

关闭或销毁窗口时销毁 webContents，确保媒体轨道停止。

## 6. 同一 checkoutUrl 的唯一窗口与接管

每个活动 session 只保留一个窗口和一个 opening Promise：

- 窗口存在：恢复、显示、聚焦，不重新 loadURL
- 正在加载：复用同一 Promise，防止双击创建多个窗口
- 窗口已销毁且会话未到期：先查询 KOD BFF，再用原 checkoutUrl 重建
- `COMPLETED`、`CANCELLED`、`EXPIRED`：不重新打开或录制
- 只有原会话过期且用户明确发起新意图才创建新会话
- 关闭窗口本身不等于取消，只触发状态查询
- 迟到的旧窗口事件通过 `webContents.id` 和 sessionId 拒绝

## 7. IPC 授权与事件处理

注册可清理的 Tinpay IPC handlers：

- 主 KOD Renderer 才能打开/关闭/外部浏览器重开 checkout
- 远程 Tinpay 窗口只能发送固定事件
- 校验精确 sender `webContents.id`、主 frame URL/origin、Schema、版本、事件类型、当前 sessionId 和过期状态
- `tinpay.completed` 等所有事件只转成 renderer 的“查询此 session”提示
- `tinpay.cancelled` 也先查询 BFF，不直接修改本地业务状态
- 完成时只有 BFF 返回 `COMPLETED` 且 `demoOnly === true` 才显示演示完成

主 Renderer 通过新增的窄类型 `electronAPI.tinpay` API 调用，不在功能代码中直接使用通用 `invoke`。

## 8. 修复并扩展 Windows 深链恢复

为 `kod://tinpay/result` 增加安全解析和恢复信号，同时修复当前冷启动仍匹配旧 `chatbox://` 的问题：

- 仅接受 `kod:` / `kod-dev:` 和精确 host/path
- 对 malformed URL 安全失败
- 限制 query 长度，不记录完整 query/callbackState
- 事件仅触发 BFF 查询
- 统一运行中 second-instance 与冷启动路径
- 不接受 URL 中的 `status=COMPLETED` 作为完成依据

由于 Electron 内置窗口存在 `window.tinpayHost`，Tinpay 正常流程不主动跳转 Scheme；该深链只用于外部浏览器降级返回。

## 9. 设置页演示入口和状态 UI

在 `/settings/chatbox-ai` 登录视图之后增加 Windows Electron 专用 Tinpay 演示卡片：

- 商品：模型调用套餐
- 演示金额：¥9.90
- “使用听付”按钮
- 固定提示：“本功能当前为体验演示，不会产生实际扣款”
- 创建中、页面加载、等待、查询中、权限拒绝、重试、过期、错误状态
- “重新打开听付演示”和“在浏览器中打开听付演示”均复用原 checkoutUrl
- 权威完成后显示：
  - “听付演示已完成”
  - “本次操作未发生真实资金扣款”
- 不修改真实余额、额度或许可证
- 不展示“付款已到账”等真实支付文案

本轮不替换现有购买按钮，降低 M1 对现有产品流程的影响。

## 10. 会话控制、轮询和恢复

新增 renderer Tinpay controller/store：

- 一次只维护一个活动 M1 会话
- 保存最小恢复数据：sessionId、checkoutUrl、expiresAt、最后状态；不保存 Bearer/callbackState
- 串行、可取消、不重叠查询
- 事件、窗口关闭、Electron focus/show 和深链都汇聚到一个去重查询函数
- 仅在等待状态轮询，达到 expiresAt 或终态后停止
- 网络失败显示“暂时无法确认”，保留人工重试
- 账号退出/切换、session 替换或组件卸载时取消旧请求

M1 为避免引入完整支付历史，先使用小型、版本化的现有 renderer storage 持久化单个活动演示会话；后续如扩展交易历史再升级为独立 IndexedDB/SQLite repository 和迁移。

## 11. i18n

新增所有用户可见文案的源语言键，并按仓库流程运行翻译同步；不手改生成的非源语言 locale 文件。

- 视环境运行相关测试套件

## 13. 联调输出和限制

代码完成后提供：

- 当前 KOD commit SHA（若未提交，则明确报告工作树 commit 和未提交状态）
- KOD package 版本
- BFF 请求使用的脱敏 X-Request-Id
- HTTP 状态、sessionId、Electron 打开结果和媒体权限结果的联调模板

不会报告伪造的成功结果。只有在以下条件同时满足后，才能实际填充首次请求结果：

1. KOD BFF 路径已部署并与建议契约兼容；
2. KOD 后端已通过私密渠道获得 Bearer；
3. 有可用 KOD 测试账号；
4. Windows 打包应用实际运行并完成摄像头/麦克风测试。

本计划不包含 KOD 后端实现、Bearer 处理或真实 Tinpay 直连，因为它们不属于当前客户端仓库且不能安全地在客户端补做。

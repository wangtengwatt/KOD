# KOD 托管算力交易闭环设计

日期：2026-08-21

状态：用户已逐节批准

OpenSpec：[`enhance-compute-hosted-marketplace`](../../../openspec/changes/enhance-compute-hosted-marketplace/)

## 1. 经确认的产品规则

1. 付款立即冻结买家卡时，排期协商、交付、使用和争议期间保持冻结；买家确认或交付后 24 小时无争议才结算卖家。
2. 买卖双方在订单内用文字和图片沟通，并通过结构化提议/确认锁定开通时间；自由文本不等同于排期。
3. 在商品承诺交付时限内没有确认排期，订单自动取消并全额解冻。
4. 聊天系统消息不可删除；完成/取消后只读；文字长期保留，图片 180 天清理。
5. 移动端本期只提供应用运行/后台期间的本地提醒，不承诺缺少 APNs/FCM 凭据时的彻底离线推送。
6. 审核记录覆盖实名认证、供应方、GPU 资质、商品和大额转让，显示审核人、对象、结果、原因和时间。
7. 下架申请提交后立即停止新接单；申请满七天且所有既有订单和争议清空后自动下架。
8. 已完成订单账户冻结为零是正确结果；订单自身必须保留原冻结、结算和退款说明。

## 2. 选择的架构

采用“后端订单聚合根 + 客户端领域组件”的渐进方案。后端是排期、资金、审核和权限的唯一事实源；客户端负责清晰呈现与收集用户意图，不在本地推断交易成功。

```text
订单
├─ 参与者（买家、卖家、管理员只读/裁决）
├─ 聊天消息与系统事件
├─ 排期提议与节点时段锁
├─ 卡时冻结分配与结算投影
├─ 交付、争议和确认
└─ 托管节点及下架阻塞关系
```

## 3. 关键状态机

```text
PENDING_SCHEDULE
  ├─ 双方确认且无冲突 → PENDING_DELIVERY
  └─ 协商超时 → CANCELLED + 全额解冻

PENDING_DELIVERY
  ├─ 卖家交付 → DELIVERED
  └─ 交付超时 → CANCELLED + 全额解冻

DELIVERED / IN_USE
  ├─ 买家确认 → COMPLETED + 结算卖家
  ├─ 24h 无争议 → COMPLETED + 结算卖家
  └─ 买家争议 → DISPUTED + 保持冻结
```

托管下架：`ACTIVE → DELIST_PENDING/停止新接单 → 等待七天与清空阻塞 → OFFLINE`。

## 4. 第一性原理结论

- “聊天”不能替代“排期锁”；否则平台无法防止同一 GPU 重叠承诺。
- “账户冻结余额”不能替代“订单资金投影”；完成订单冻结归零仍需说明原冻结去向。
- “现有审计表”不能替代“审核证据快照”；若商品之后可变，历史审核记录就无法证明审核了什么。
- “申请后继续接单”与“清空后下架”互相矛盾，因此申请时必须立即停止新订单。

## 5. 用户体验

- 审核中心使用待审核/审核记录页签和统一状态色，审核卡直接显示图片、资质与完整参数。
- 租赁订单是唯一订单入口，提供我购买的/我出租的筛选、聊天、排期、资金时间线和交付/争议动作。
- 我的设备包含算力托管概览、节点、商品、排期、运行订单和下架申请。
- 所有写入反馈使用现有居中浅绿/浅红通知模式；聊天新消息另外显示红点和本地通知。

## 6. 安全与数据保留

- 订单消息/图片只允许参与者读取；资质图只允许所属供应方和管理员读取。
- 禁止聊天附件中的脚本和可执行文件；图片由服务端验证内容类型和体积。
- 本地通知不显示敏感正文；SSH 密码和私钥继续禁止进入平台。
- 自动化测试完全隔离；真实数据库仅执行已有登录状态、商品、资产、订单等只读冒烟。

## 7. 交付边界

本设计不改变人民币充值、卡时汇率、零售站/节点选择、对话、生图、生视频或 Token 套餐代理。客户端基线为 `0c7fb6b`，后端基线为 `1c5a63d`；两端均推送 `suanlizhongxin_KOD`。

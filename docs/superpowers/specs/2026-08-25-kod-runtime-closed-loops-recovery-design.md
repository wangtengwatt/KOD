# KOD 客户端运行闭环恢复设计

## 背景

当前客户端已经包含官网账户、钱包、广告奖励、邀请好友、实时行情和卡时托管的主要界面与协议，但生产运行时出现了五类断点：官网数据与客户端身份不同步、充值记录解析失败、行情代理未形成可用链路、广告素材无法播放、邀请入口重复，以及卡时托管缺少可验证的一键开通闭环。

同事的客户端行情提交 `b8c66432632bfa688cb34eccc8e8e4981e7160c3` 与门户代理提交 `82bcbeecf6a6f13dbce7c6245300b5f0cd48fca5` 是行情实现的权威来源。本次只恢复它们与生产部署的连接，不重写行情产品设计。

## 已确认目标

1. 官网账户是余额、卡时和充值记录的唯一事实来源，客户端登录、刷新、返回前台和手动刷新后读取同一账户数据。
2. 行情界面完整采用同事实作，并通过官网同源只读代理访问共享行情服务。
3. 看广告页面继续使用 `C:\Users\Microsoft\Desktop\kod广告.mp4` 作为初始 KOD 宣传素材，后台以后可以安全替换。
4. 左侧只保留“邀请好友”，其中完成邮箱邀请、链接复制、待处理/已接受跟踪和 10 奖励卡时到账提示；旧人民币佣金只保留审计数据。
5. “卡时托管”完成 KAI 服务器按月租用、自动上架、平台统一定价、收入入账、默认自动续租和到期退出闭环。
6. 广告和邀请奖励卡时只可用于普通平台消费，不可回购、不可支付托管月租；人民币购买、算力销售和托管收入形成的可回购卡时可支付托管月租并可回购。
7. 最终交付到两个仓库的 `suanlizhongxin_KOD` 分支，部署官网生产环境，重建 Windows 客户端并同步现有桌面快捷启动方式。
8. 已部署官网前端页面的结构、文案布局和绿色白色视觉保持不变；KAI Logo 是不可修改资产。服务接线不得借机重做官网 UI。

## 设计决策

### 1. 以服务端账户标识隔离所有查询

认证结果持久化稳定的 `accountId`。所有官网钱包、充值历史、卡时账户、订单、邀请、广告和托管查询键都包含账户标识。令牌刷新不得清除仍有效的账户标识；如果请求发出后账户从 A 切换到 B，A 的响应不得写入 B 的缓存，也不得以 B 的令牌重放 A 的请求。

客户端仅在服务端明确返回未认证时退出登录。网络超时、5xx 或响应格式错误显示可重试错误并保留会话。所有可能超过 JavaScript 安全整数范围的账户、订单、邀请、租约、节点和产品 ID 以十进制字符串传输和比较；金额和卡时精度也使用字符串边界，界面展示时才格式化。

### 2. 官网数据采用统一刷新事务

钱包余额、卡时分桶和充值记录使用同一认证上下文刷新。充值完成回到官网或客户端、窗口重新获得焦点、用户手动刷新时，统一失效当前账户的相关查询。解析失败不会显示旧账户数据；界面提供明确的“数据格式异常/重新加载”状态。

### 3. 行情完整遵循同事实现

客户端保留同事的共享行情适配器、版本化契约、单位、刷新节奏、错误状态和来源说明。生产默认访问 `https://kod.kai.com/api/v1`，只允许配置的 HTTPS 来源、不携带用户凭据。服务端代理负责 `/api/v1/contracts`、`/api/v1/dashboard/*`、`/api/v1/health/live` 与 `/ws/dashboard`。代理不可用时显示可重试的不可用状态，不用本机伪造数据冒充远程行情。

### 4. 广告素材走同源可续传媒体接口

后台活动返回同源素材 URL、MIME、实际时长、最少观看时长和海报。媒体端点支持浏览器/Electron 的 `Range` 请求、`206 Partial Content`、正确 `Content-Type` 和缓存验证。客户端显示加载与重试状态，只有服务端确认有效播放进度和完整观看后才允许每日一次的 10 奖励卡时领取。

### 5. 邀请功能只保留一个用户入口

侧边栏“邀请好友”抽屉是唯一用户入口。抽屉包含邮箱输入、复制注册链接、近 90 天邀请列表和状态颜色：待处理为中性/灰色，已接受为绿色，失效或失败为红色并显示安全原因。好友使用该邮箱完成 KOD 注册与邮箱验证时，服务端原子接受邀请并给邀请人发放一次 10 奖励卡时。旧“历史邀请佣金”页从用户导航移除，历史人民币佣金记录不删除，继续作为只读审计数据。

### 6. 卡时托管以一个月租事务开通

用户选择平台可售 KAI 服务器 SKU 并确认月租。服务端在一个幂等事务中锁定账户和库存，仅扣可回购卡时，创建租约、托管节点和平台统一价格商品，然后返回可追踪状态。默认开启自动续租；用户关闭后当前租期仍有效，到期先停止接新单，完成存量履约后下架并释放库存。

托管销售收入进入可回购卡时。界面集中展示服务器规格、月租、统一售价、租期、上架状态、累计收益、下一次续租时间和退出操作。供应方不得购买或调用自己的商品，避免把奖励卡时洗成可回购收入。

## 测试与验收

行为修改全部按 RED-GREEN-REFACTOR 实施。写入型闭环测试只在隔离数据库和隔离行情/媒体服务中执行；生产仅执行只读健康检查、真实登录后的账户读取和页面渲染验收。

最低验收覆盖：

- A/B 账户切换、令牌刷新、网络故障和大整数 ID 不串号；
- 官网余额、卡时分桶和充值记录在客户端刷新后与同账户官网一致；
- 同事行情 HTTP 与 WebSocket 路径可达，页面按原实现渲染并在断网时正确报错；
- 原始 KOD 广告可播放、可续传、看完到账 10 卡时且每日不可重复；
- 邮箱邀请从创建到注册接受再到账 10 卡时完整闭环，旧佣金入口不再重复出现；
- 托管从月租扣款到节点/商品自动创建、成交收益、续租关闭和到期退出完整闭环；
- 聚焦测试、相关回归、类型检查、Biome、生产构建、严格 OpenSpec、敏感信息与保护范围扫描通过；
- 官网生产只读验收通过，Windows 客户端构建完成，桌面快捷方式解析到最新验证版本。

## 保护范围与回滚

KAI/KOD 品牌、KAI Logo、官网当前绿色白色界面、用户余额、订单、邀请、市场、租约和历史佣金数据均受保护。官网前端页面文件默认禁止修改，若运行接线确需配置变更也不得改变渲染结果，并须通过构建前后的页面截图与受保护文件哈希比较。禁止数据库重置、演示数据覆盖、客户端密钥和支付密钥入库。每个仓库实施前创建可恢复 Git 检查点；每个部署阶段保留旧镜像和数据库向前兼容。出现任何合并冲突时停止并让用户选择。回滚应用版本时保留新增账本、邀请和租约数据，避免重复奖励、重复扣款或库存丢失。

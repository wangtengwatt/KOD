# KOD Android 全客户端功能复刻设计

## 1. 目标

将 `suanlizhongxin_KOD` 设为 KOD 唯一产品功能源，使 Windows、Web 和 Android 共享业务规则、后端数据、状态枚举、错误码和发布节奏。Android 不做桌面页面的简单缩放版，而是提供移动端适配后的完整能力；Electron 专属能力通过 Android 原生适配器或 KOD 云端执行实现。

最终验收以真实 Android 手机安装后直接连接 `https://kod.kai.com` 的线上服务为准。本机 `10.0.2.2:8080` 仅用于开发和模拟器调试，不属于最终生产交付。

## 2. 已确认的产品原则

1. 业务能力、数据和结果与 Windows 一致，界面按手机重新排版，不追求像素级复制。
2. Windows 的 `suanlizhongxin_KOD` 分支是唯一功能源；Android 分支只保留平台适配和迁移期间的集成工作。
3. 对话、媒体历史、知识库、模型与零售站配置需要跨设备同步。
4. 人民币钱包、充值、卡时、收益、订单和审核状态继续以现有后端账本为唯一真实来源。
5. 现有人民币钱包、充值和交易表不改结构；跨设备同步使用独立表和接口，通过用户 ID 关联。
6. API Key 等敏感数据服务端加密、客户端默认脱敏、重新验证后限时查看；SSH 私钥永不上传或同步。
7. 同时编辑发生冲突时保留双方内容并生成冲突副本，不使用静默的最后写入覆盖。
8. 断网可读缓存和编辑草稿，登录、调用、充值、交易和审核必须联网。
9. 删除的同步内容进入服务端回收站 30 天，用户可以提前永久删除。
10. 测试使用独立环境和模拟资金账户，不以生产人民币钱包承担全流程自动化测试。

## 3. 范围

### 3.1 必须复刻的业务模块

- 账号：登录、注册、验证码、邀请码、新老用户判断、账号切换、退出、角色标签、管理员入口。
- 对话：会话与消息历史、附件、联网搜索、模型选择、手动零售站/节点切换、额度耗尽后的最后一次完整返回。
- 生图：模型、参数、参考图、进度、失败重试、历史、保存和分享；不改变现有生图接口及路由逻辑。
- 视频：模型、参数、进度、失败重试、历史、保存和分享。
- 模型配置：供应商、默认模型、KOD 模型、零售站、节点和当前选择跨端同步。
- 知识库：创建、上传、解析、检索、引用、目录与文件跨端同步。
- MCP、技能和任务沙箱：Android 提供相同任务入口、授权、进度、取消和结果展示，执行发生在隔离的 KOD 云端运行环境。
- 人民币钱包：官网充值、返回应用刷新、余额与交易记录、人民币兑换卡时、卡时不足补差购买。
- 算力中心：市场、卡时资产、我的资产、购买记录、订单、通知、转让、邀请奖励、供应方、实名、GPU 商品、图片、交付、争议、收益和提现申请。
- Token 套餐：展示模型、输入/输出余额、Base URL、平台代理 Key、API 格式和复制按钮；套餐 Key 仅可调用购买时指定的模型。
- GPU 订单：买方提交公钥、商家交付、24 小时无争议自动确认、卡时结算和订单结束；平台不保存供应方 SSH 私钥。
- 管理后台：实名认证、供应方、设备、商品、订单、争议、提现和运营设置；本人提交的数据继续由另一名管理员审核。
- 蒜宝：移动悬浮窗、无障碍和文件访问默认关闭，逐项解释并由用户主动开启；拒绝不影响对话、生图、视频和算力中心。
- 设置：默认简体中文，保留英文和繁体中文；通知只做应用内通知中心。

### 3.2 不采用的实现方式

- 不维护两套独立业务代码并人工复制功能。
- 不用 WebView 简单套官网替代完整 Android 客户端。
- 不在 Android 本机直接运行任意 MCP 命令、技能脚本或桌面任务沙箱。
- 不建立第二份本地资金账本，不根据客户端缓存推断可用余额。
- 不提供只有入口、点击后提示“暂不支持”的假功能。

## 4. 总体架构

### 4.1 共享核心

共享层承载领域类型、API 契约、业务状态、表单校验、状态管理、错误映射、多语言键和可复用页面组件。Windows、Web 和 Android 都从同一共享层构建。

所有平台差异通过明确接口进入：

- `DesktopPlatform`：Electron IPC、本地文件、系统集成、本地 MCP 和本地任务沙箱。
- `MobilePlatform`：Capacitor、Android 原生插件、系统文件选择器、SQLite 缓存和移动权限。
- `WebPlatform`：浏览器存储、浏览器文件 API 和网页导航。
- 云任务适配器：为 Android 承接 MCP、技能和任务沙箱执行，返回统一任务状态与结果。

共享组件不得直接调用 Electron、Android 或浏览器专属 API。需要平台能力时，必须扩展统一接口并为各平台提供实现和契约测试。

### 4.2 后端边界

`kod-ai-portal release/3.0` 提供：

- 统一账号身份、令牌续期和设备会话。
- 现有钱包、卡时、订单、角色和审核数据的权威读取及交易操作。
- 对话、媒体、知识库和配置的跨设备增量同步。
- 加密密钥保险库和重新验证流程。
- 隔离的云任务提交、进度、取消、结果和审计接口。
- 对象存储上传、下载、断点续传和删除接口。

现有资金表不改结构；同步、设备、版本、冲突、回收站、云任务和密钥保险库使用独立表。

### 4.3 发布边界

迁移期间保留 Android 功能分支，避免一次性覆盖已经完成的移动导航、蒜宝插件、权限策略、SQLite 和离线适配。迁移完成且验收通过后，移动适配合并回唯一功能源。

CI 对每次功能源更新执行共享测试、后端契约测试、Windows 构建、Android 构建和平台兼容检查。任何必需能力缺少移动映射或测试失败时阻止发布。

## 5. 数据模型与同步

### 5.1 数据权威来源

| 数据 | 权威来源 | 客户端行为 |
| --- | --- | --- |
| 人民币、充值、卡时、收益、订单、角色、审核 | 现有后端数据库 | 联网读取，短期缓存只用于展示 |
| 对话、消息、媒体历史、知识库目录、模型与节点配置 | 新同步服务 | 服务端权威，本地 SQLite/IndexedDB 缓存 |
| API Key 等密钥 | 加密密钥保险库 | 默认只返回掩码，重新验证后限时读取 |
| SSH 私钥 | 供应方自己的设备 | KOD 不接收、不保存、不同步 |

### 5.2 同步协议

每条同步记录至少包含用户 ID、记录 ID、设备 ID、版本号、更新时间、内容哈希和删除标记。客户端按服务端游标拉取增量变更，并以幂等操作 ID 上传本地变更。

写入需要携带客户端看到的版本号。版本一致时更新；版本冲突时保存远端版本和本地版本，创建带来源设备与时间的冲突副本，并通知用户处理。任何客户端都不能静默覆盖未见过的版本。

离线写入进入本地操作队列。恢复联网后按照依赖顺序上传；可重试错误使用指数退避，永久错误保留操作和明确原因。资金、审核和模型调用不进入离线队列。

### 5.3 文件与删除

图片、视频、知识库文件存入对象存储，数据库保存元数据、权限、校验哈希和生命周期。上传支持分片、断点续传和完整性校验。

普通删除写入墓碑并进入 30 天回收站；恢复操作创建新版本。提前永久删除会清除对象存储文件、同步记录和设备缓存索引，并保留不含敏感内容的审计事件。

## 6. 安全设计

- 密钥在传输中使用 TLS，在服务端使用独立密钥管理能力加密。
- 客户端普通接口只返回密钥掩码，不把完整密钥写入日志、崩溃报告或同步缓存。
- 查看或复制完整密钥需要近期重新验证；授权短时有效并写入审计记录。
- 身份证号、证件文件地址、API Key、Token 和 SSH 信息在日志中脱敏。
- 云任务在隔离环境运行，配置 CPU、内存、时长、网络和文件范围限制，并支持用户取消。
- Android 权限默认关闭，使用对应能力时再逐项申请；拒绝权限不得降低无关功能。
- 生产接口按照最小权限执行，管理操作校验角色，双管理员审核规则由后端强制而不是只靠前端隐藏按钮。

## 7. 移动交互设计

Android 使用底部导航承载对话、生图、视频、算力和“我的”。复杂桌面多栏页面改为分步表单、横向可滚动标签、抽屉和独立详情页。

零售站和节点切换只保留输入框上方的一组移动快捷选择，不增加第二套选择器。切换结果与 Windows 使用同一配置记录同步。

全局操作反馈显示在屏幕上方居中：成功浅绿色、失败浅红色，默认 3 秒关闭，支持关闭按钮和点击空白区域消除。页面靠下操作时不依赖页面顶部的静态提示。

充值使用系统浏览器打开官网，返回应用后从服务端刷新人民币余额。登录和钱包使用同一账号状态，不允许模型配置已登录而“我的”显示未登录。

## 8. 错误与一致性保护

- 登录令牌和用户资料由统一会话服务管理；401 先尝试一次令牌续期，失败后统一退出。
- 兑换、购买、转让、提现和结算携带幂等键并在后端事务内完成，重复点击或网络重试不能重复扣款。
- API 错误返回稳定错误码、请求编号、服务名称和用户可执行建议，不向客户端暴露堆栈和密钥。
- 云任务支持排队、运行、取消、失败和超时状态；失败不会影响普通对话。
- 后端旧版本不支持某能力时通过服务能力清单隐藏未启用入口，客户端不能因字段缺失崩溃。
- 发布采用灰度和可回滚版本；数据库变更必须向前兼容当前已发布客户端。

## 9. 测试与验收

### 9.1 功能对照清单

建立机器可读的功能对照清单。每个 Windows 功能必须映射为 Android 原生实现、共享实现或云端实现，并关联入口、权限、API 和测试。未映射功能会使 CI 失败。

### 9.2 自动化测试

- 共享单元测试：业务规则、状态转换、错误映射和平台接口。
- 后端集成测试：登录续期、增量同步、冲突副本、幂等资金操作、余额补差、订单结算、删除恢复和密钥脱敏。
- API 契约测试：Windows、Android 与后端字段、枚举、版本兼容和错误码一致。
- Android UI 测试：角色页面、移动导航、表单、离线、充值返回、权限拒绝和错误反馈。
- 构建矩阵：Android 8、12、15；Windows 构建；共享 TypeScript 检查。

新增行为必须按测试先行完成：先运行测试并确认因能力缺失而失败，再写最小实现使其通过，最后运行相关回归测试。

### 9.3 业务验收环境

建立独立测试后端、测试数据库、对象存储空间和模拟资金账户。至少包含购买方、已认证供应方和算力管理员，并覆盖：入驻、实名、设备、商品、购买、人民币补差、交付、确认、收益、争议、提现申请、Token 套餐调用和额度耗尽。

生产环境只进行只读冒烟和授权的小额验证，自动化测试不得修改真实钱包或真实订单。

### 9.4 完成标准

一个模块只有同时满足下列条件才可标记完成：

1. Windows 已启用能力在 Android 有可用入口。
2. Android 使用同一后端数据和业务状态。
3. 成功、失败、离线和权限拒绝均有明确处理。
4. 自动化测试、构建和真实手机验收通过。
5. 功能对照清单中不存在未实现或仅占位项。

## 10. 迁移顺序

1. 建立功能对照清单、共享平台接口和 CI 阻断规则。
2. 统一账号会话、生产 API 地址和能力清单。
3. 建立同步服务、本地缓存、冲突副本、对象存储与回收站。
4. 将对话、媒体、模型配置和知识库接入共享同步。
5. 将桌面专属 MCP、技能和任务沙箱接入云任务适配器。
6. 对齐钱包、算力中心、供应方和管理员全流程。
7. 完成 Android 8/12/15、真实手机、弱网、离线和权限验收。
8. 生成 Debug APK、测试报告和功能对照清单；生产部署后生成独立签名 Release APK。

## 11. 已知约束

- 在后端未部署同步和云任务接口前，真实手机无法仅靠 APK 获得完整跨端能力。
- Android 无法安全地原样执行 Electron 主进程、本地任意命令和桌面文件系统操作，必须使用移动适配或云端执行。
- 当前本机 Debug APK 指向模拟器宿主机，不可作为生产联网验收结论。
- “界面已经出现”不等于“功能完成”；资金、订单、同步和云任务必须以端到端测试结果为准。

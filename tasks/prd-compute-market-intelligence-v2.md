# PRD：KOD 算力中心演示模拟行情 V2

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | KOD 算力中心演示模拟行情 V2（Compute Market Simulator） |
| 目标平台 | KOD Windows/macOS/Linux 客户端、Web 端 |
| 目标入口 | `算力中心 > 算力市场 > 实时行情` |
| 状态 | 实施中：P0 核心链路完成，P1/P2 已启动，P3 完成契约与隔离基线 |
| 发布方式 | P0 → P1 → P2 → P3 分阶段交付；源码与新生产构建默认连接 KOD 线上共享模拟行情 |
| 核心原则 | 保留 KOD 产品外壳，以可复现模拟引擎驱动完整行情演示；页面底部持续披露，且与真实钱包、订单和交易完全隔离 |

## 2. 背景与问题

KOD 已在算力中心提供全球 GPU 行情页面，当前能力包括 GPU 型号与时间范围选择、报价卡片、历史价格折线和
型号价格速览。现有实现集中在
`src/renderer/routes/compute-center.tsx` 的 `MarketPricePanel` 中，使用以下接口每 5 秒轮询：

- `GET /api/compute/market-prices/latest`
- `GET /api/compute/market-prices/history`

现状不能稳定支撑近期演示，且存在以下问题：

1. 最新快照和完整历史数据都以 5 秒频率重复请求，网络开销和图表更新成本不必要地偏高。
2. 行情页面与算力中心其他业务共处一个大路由文件，难以独立测试和演进。
3. 数据来源被固定为两家，表格列、颜色和图例无法随演示场景动态扩展。
4. 缺少统一的模拟标的、计价单位、场景、种子、模拟时钟、质量状态和能力声明契约。
5. 尚未形成 KOD 卡时行情、模型 API 价格和全球 GPU 参考价之间清晰且不可混淆的信息架构。
6. 缺少可控的模拟增量、暂停恢复、事件顺序和快照校准机制。
7. “算力期货大屏”的行情工作台、全屏展示、模拟成交与盘口机制适合本次演示目标，但需要以 React、Mantine 和
   KOD 视觉重新实现，并通过确定性种子、统一状态和资产隔离消除不可复现及误接真实业务的风险。

因此，本项目采用“能力融合而非项目合仓”：继续由 KOD 承载导航和产品外壳，以 React、Mantine 和 TanStack
Query 重写行情体验；行情、成交、挂牌深度、盘口和持仓演示均由独立模拟域生成。模拟域不得读取或写入 KOD
真实钱包、卡时余额、订单、资产、支付、广告奖励或结算数据。

### 2.1 当前线上基线（2026-08-21）

- `/api/compute/market-prices/latest` 当前返回 HTTP 500。
- `/api/compute/market-prices/history` 当前返回 HTTP 500。
- `/api/compute/card-hours/market/stats` 当前返回 HTTP 200，但库存与成交统计均为 0。

这意味着真实行情模式当前不可发布，但不阻断本 PRD 的演示模拟模式。模拟模式不请求上述三个真实接口，不把
HTTP 500 或真实空市场自动降级成模拟值；启用模式必须由受信的构建/部署配置明确决定。真实接口恢复仍是未来
真实行情模式的独立发布门槛，不属于本轮模拟演示验收。

### 2.2 方向调整与实施基线（2026-08-21）

- **已有基础：** 新行情模块已挂载到原“实时行情”入口，并保留旧面板作为功能开关回退；KOD 主题、GPU/卡时
  分区、报价与趋势、全屏、契约校验、窄屏适配和测试基础可复用。
- **本轮调整：** 页面数据源改为服务器统一运行的确定性模拟引擎。相同 `seed + scenario + engineVersion` 必须生成
  相同初始历史和事件序列；禁止在组件渲染过程中直接使用无种子的 `Math.random()` 形成不可复现数据。
- **披露方式：** 客户端、Web 与全屏模式的页面最底部持续显示小字：“本页行情、盘口、成交及方向均由模拟行情
  服务生成，仅用于产品演示，不构成真实市场或交易依据。”不要求在每张卡片、每个图表重复展示徽标。
- **隔离方式：** 模拟模式使用独立 Query Key、存储命名空间、会话、账户和事件总线；不得调用钱包、充值、支付、
  广告奖励、真实订单、资产、结算或真实行情写接口。切换模式必须清空对应缓存，禁止数据跨模式复用。
- **发布方式：** 源码拉取和新生产构建默认启用模拟模式并连接 `https://kod.kai.com/api/v1`；服务不可用、配置无效
  或数据为空时显示错误，禁止回退为每台设备各自生成的数据。开发者仍可通过构建环境变量显式切换本地服务。

## 3. 目标

1. 在不破坏现有算力市场、我的资产、我的订单等业务的前提下升级“实时行情”嵌套页面。
2. UI 色彩、排版、间距、圆角、边框、空状态和交互反馈与 KOD 客户端保持一致，并同时适配 Web。
3. 建立全球 GPU、KOD 卡时和模型 API 三类模拟行情的独立计价和展示边界。
4. 由同一个模拟时钟和确定性事件引擎生成快照、历史、增量、挂牌、成交与盘口，支持暂停、恢复、倍速和场景重置。
5. 模拟价格、成交、供应、盘口和运行指标在同一场景内前后一致；缺失值不得以 0 代替。
6. 页面底部持续以小字完成模拟性质和资产隔离披露，同时避免在每个组件重复干扰演示视觉。
7. 建立环境开关、缓存隔离、自动化验收和快速回滚路径，确保模拟数据绝不进入真实业务链路。

## 4. 非目标

- 不直接执行两个仓库的 Git merge，不嵌入 Vue 应用或 iframe。
- 不迁移“算力期货大屏”的 AppShell、Router、侧边栏、Agent 抽屉、全局 CSS、Grafana 和治理页面。
- 不直接复制原 Vue Simulator；模拟逻辑在 KOD 代码中重写并提供种子、场景、版本与一致性约束。
- 不把任何模拟报价、成交、K 线、盘口、持仓或盈亏写入或描述为真实市场事实。
- 不在 P0/P1/P2/P3 建设或调用真实期货交易、撮合、开平仓、持仓、保证金、风控、清算和结算系统。
- 不让客户端或 Web 端直接连接 ClickHouse、Redis、第三方供应商或真实行情接口，也不持有供应商密钥。
- 不访问或修改真实钱包、卡时余额、广告奖励、充值、支付、订单、资产和账本。
- 不在真实接口失败时静默回退到模拟行情；真实与模拟模式必须由受信配置显式选择。
- 不把 GPU 租赁价、卡时价和 Token 价转换后放进同一曲线或跨单位排行榜。
- 不在行情页面承载完整的节点运维监控；Token 速率、缓存命中率、P95 等属于设备或供应商运营域。
- 不以固定 1920×1080 画布作为常规页面布局，也不通过整体缩放适配小屏。

## 5. 用户与核心场景

### 5.1 目标用户

- 算力采购方：比较 GPU 租赁参考价、KOD 卡时供应和模型 API 价格。
- KOD 卡时用户：通过演示模拟行情理解挂牌、成交和卡时市场信息结构，不把页面数值当作真实资产价值。
- 算力供应方：演示同规格市场供给、价格区间和容量变化场景。
- 演示与运营人员：在常规或全屏模式演示连续变化的模拟行情、成交与市场结构。

### 5.2 核心用户故事

- 作为未登录访客，我可以查看演示模拟行情，不需要先进入钱包或登录。
- 作为采购方，我可以在同一类、同单位的标的中切换型号、区域、场景和时间范围。
- 作为用户，我能看到模拟时钟、引擎运行/暂停/回放/异常状态和最后更新时间。
- 作为用户，我能在页面最底部持续看到模拟性质以及“不影响钱包、卡时、订单或资产”的小字说明。
- 作为演示人员，我可以选择预置场景、重置相同种子并复现相同的行情过程。
- 作为演示人员，我可以打开 KOD 风格的全屏行情，并看到与常规页面一致的模拟报价、成交和盘口状态。

## 6. 产品与数据原则

### 6.1 唯一产品外壳

- 保留 KOD 的算力中心导航、主题、登录、钱包、资产、订单、设备和权限体系。
- 只替换“实时行情”嵌套面板，不替换 `/compute-center` 路由和其他标签页。
- 行情组件作为独立 `market-intelligence` 模块实现，通过现有 KOD 请求封装访问后端。
- 模拟行情页不跳转到真实购买、预订、钱包或订单页面；如 P3 提供模拟操作，只进入独立沙盒闭环。

### 6.2 计价单位隔离

| 行情类别 | 允许单位 | 模拟来源 | 允许的展示语义 |
| --- | --- | --- | --- |
| 全球 GPU 参考价 | USD/GPU·小时、CNY/GPU·小时 | KOD 模拟引擎 GPU 场景 | 报价、样本量、价格趋势 |
| KOD 卡时行情 | CNY/卡时、卡时 | KOD 模拟引擎卡时场景 | 挂牌供应、供应深度、成交 |
| 模型 API 价格 | CNY/1M 输入 Token、CNY/1M 输出 Token | KOD 模拟引擎模型场景 | 套餐价、输入价、输出价 |

规则：

- 不同单位不得默认叠加在同一纵轴、求均值、计算涨跌排名或称为同一价格指数。
- 汇率或卡时换算值必须标记为“换算”，同时保留原始价格、汇率版本和换算时间。
- `null`、缺失或不可用必须显示“暂无报价/暂无数据”，禁止通过 `|| 0` 进入 UI。
- 同类比较至少要求 `marketKind + gpuModel/model + region + runtime + delivery + priceUnit` 可比。

### 6.3 模拟数据契约与一致性

模拟模式下每条标的、快照、序列、成交、深度和持仓都必须携带 `dataMode=SIMULATED`，并可追溯到以下元数据：

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `simulationSessionId` | 当前模拟会话 | 与真实用户、钱包和订单 ID 无关联 |
| `seed` | 确定性随机种子 | 同版本、同场景、同种子结果可复现 |
| `scenario` | 演示场景 | 例如 `NORMAL`、`VOLATILE`、`SUPPLY_SHOCK`、`RECOVERY` |
| `engineVersion` | 模拟器算法版本 | 算法变化必须升级版本，避免错误复现 |
| `simulatedAt` | 模拟市场时钟 | UI 时间轴统一使用该时钟，不冒充真实采集时间 |
| `sequence` | 事件顺序 | 严格递增，用于去重、乱序和重置校验 |

规则：

- 报价、K 线、成交、挂牌深度、双边盘口、容量、SLA 与 P3 沙盒持仓必须由同一个会话状态推导，禁止各组件独立
  随机导致价格、成交量和持仓互相矛盾。
- 可以使用带种子的伪随机算法制造自然波动，但必须设置价格、容量、波动率和事件频率边界，并能一键重置。
- 页面主体可以沿用“行情、成交、盘口”等市场术语；模拟披露集中在页面最底部持续小字，不要求每个数据点重复标记。
- `SIMULATED` 数据不得转换成任何真实数据模式，也不得写入真实 API、缓存、数据库表、钱包、订单或埋点明细。

### 6.4 模拟引擎状态

统一支持：

- `RUNNING`：模拟时钟和事件正常推进。
- `PAUSED`：因用户操作、页面后台或演示控制暂停，保留当前快照。
- `REPLAYING`：从预置种子和场景重新播放。
- `STALE`：事件循环超过阈值未推进，仍可显示最后模拟快照并标注时间。
- `UNAVAILABLE`：模拟器初始化或运行失败。
- `BLOCKED`：Schema、序列、单位或隔离检查失败，停止继续应用事件。

严重程度、颜色和文案由统一映射表管理；状态表达必须同时包含文字或图标，不能只依赖颜色。

## 7. 信息架构与交互

### 7.1 导航

```text
算力中心
└─ 算力市场
   ├─ 商品/套餐（既有）
   └─ 实时行情
      ├─ 全球 GPU 参考价
      ├─ KOD 卡时行情
      └─ 模型 API 价格
```

P0 按预置场景展示已实现的模拟类别；未实现的类别显示“即将开放”，不得通过跨类别复制数值补齐。

### 7.2 常规行情页

```text
[行情类别] [标的/型号] [区域] [场景] [时间范围]       [行情状态] [更新时间]

[最新值] [24H 涨跌/区间] [成交量或样本量] [库存/容量]

[                    价格趋势 / K线 + 成交量                     ] [市场摘要]
[                    场景、单位与更新时间说明                    ] [行情状态]

[成交 / 挂牌供应深度 / 同类比较（按阶段显示）]        [进入全屏展示]

[页面底部持续小字：模拟行情，仅供产品演示；数据不代表真实市场，不影响钱包、卡时、订单或资产。]
```

展示规则：

- `seriesKind=SIMULATED_QUOTE` 显示价格趋势；`seriesKind=SIMULATED_OHLCV` 显示由同一模拟成交序列聚合的蜡烛图和成交量。
- 只有 `capabilities.simulatedTradeTape=true` 时显示成交列表；成交编号、方向、价格、数量和时间来自同一模拟事件。
- `simulatedSupplyDepth` 表示挂牌供应分桶；`simulatedOrderBook` 表示 P2/P3 双边沙盒订单簿，类型和标题不得混用。
- 只有同一可比组存在至少两个有效模拟标的时显示“同类比较”，至少两个模拟交付期限时显示“期限结构”。
- 模拟器缺少某项能力时默认隐藏对应模块，不能由 UI 临时生成独立随机值补位。
- 页面最底部的小字在常规页、滚动页与全屏模式中持续可见，推荐 `12px`、主题弱化文本色且满足可读对比度；
  不使用顶部横幅、弹窗或每卡徽标重复打断演示。

### 7.3 KOD 视觉规范

- 使用 Mantine 和 KOD 现有设计 Token：页面背景、卡片背景、边框、正文、`chatbox-tertiary`、圆角和阴影。
- 默认使用 KOD 浅色中性视觉，并自然支持现有深色主题；禁止复制深蓝底、荧光青、赛博网格等大屏主题。
- 除成功、警告、错误、信息等语义状态外，不硬编码业务颜色；图表系列颜色来自主题化调色板。
- 卡片使用 KOD 现有 `Paper/Card withBorder` 语言；标题、筛选器、按钮和空状态沿用客户端尺寸体系。
- 不新增重复的侧边栏、标题栏、面包屑或 Agent 抽屉。
- 加载使用骨架屏；刷新不得清空已成功数据或造成整页闪烁。
- 模拟行情披露固定在页面最底部持续可见，不能藏在 Tooltip、折叠面板或仅首次出现的弹窗中。

### 7.4 响应式

| 视口 | 布局 |
| --- | --- |
| `>= 1200px` | KPI 横排；图表与摘要约 2:1 双列；表格完整显示 |
| `768–1199px` | KPI 两列；图表独占一行；摘要与引擎状态两列或单列 |
| `< 768px` | 所有模块单列；筛选器可换行/抽屉化；表格横向滚动；图表高度不低于 240px |

桌面和 Web 共用组件，不依据运行平台复制两套 UI。全屏行情是独立响应式页面/模式，不使用固定画布整体缩放。

## 8. 分阶段范围与验收

### 8.1 P0：KOD 风格模拟行情基础版

目标：完成模块拆分、KOD 视觉统一、确定性基础行情和模拟/真实业务硬隔离。

任务：

- [ ] `P0-01` 新建独立 `market-intelligence` 模块，将行情 UI、模拟器、格式化和状态映射移出大路由文件。
- [ ] `P0-02` 仅在现有“实时行情”入口挂载新面板，保留算力中心外层和其他业务页面。
- [ ] `P0-03` 实现确定性模拟数据适配器，输出 GPU、卡时和模型 API 的标的目录、快照与历史趋势。
- [ ] `P0-04` 支持类别、型号、场景、时间范围筛选；筛选状态可恢复，但模拟数据缓存使用独立命名空间。
- [ ] `P0-05` 实现报价卡、趋势、型号速览、场景和更新时间说明；缺失值保持缺失，不使用 `|| 0`。
- [ ] `P0-06` 实现 `RUNNING`、`PAUSED`、`STALE`、`UNAVAILABLE`、`BLOCKED`、错误和重试状态。
- [ ] `P0-07` 在常规、滚动和全屏页面最底部持续显示约定的小字披露，不增加顶部警示条或逐卡徽标。

## 9. 模拟行情契约草案

### 9.1 通用约定

- 模拟契约优先通过客户端模块或 Web Worker 交付；如使用专用演示服务，保持 `{ code, message, data }` 响应信封。
- 时间使用 ISO 8601 UTC；价格使用十进制定点字符串，前端禁止依赖二进制浮点进行账务计算。
- 可选数值缺失使用 `null` 或省略，不使用 0 代表未知。
- 所有契约包含 `schemaVersion`；未知主版本进入 `BLOCKED`，不得尽力猜测。
- 所有对象包含 `dataMode=SIMULATED`、`simulationSessionId`、`seed`、`scenario`、`engineVersion` 和模拟时间。
- 模拟契约不接收或返回真实用户账户、订单、钱包、卡时余额、广告奖励、支付字段、供应商密钥或内部错误栈。
- 模拟数据不提供冒充真实来源的外链；引擎来源统一标识为 `KOD_SIMULATOR`。

### 9.4 历史序列

`simulator.getSeries({ instrumentId, range: '24h', interval: '1m', seriesKind: 'SIMULATED_QUOTE' })`

- `seriesKind=SIMULATED_QUOTE`：返回模拟时间、报价、样本量和状态。

- 模拟器限制时间范围、点数和间隔；客户端最多渲染 2,000 个可见点，超出后按固定算法降采样。

### 9.5 模拟增量流

`simulator.subscribe({ instrumentId })`，默认由 Web Worker/进程内事件总线提供；专用演示服务可使用同语义 WebSocket/SSE。

```json
{
  "schemaVersion": "2.0",
  "dataMode": "SIMULATED",
  "simulationSessionId": "sim_session_01",
  "eventId": "evt_01J5...",
  "eventType": "QUOTE_UPDATED",
  "instrumentId": "sim:gpu-ref:h100:global",
  "sequence": 12888,
  "simulatedAt": "2026-08-21T08:00:05Z",
  "generatedAt": "2026-08-21T08:00:06Z",
  "payload": {
    "status": "RUNNING",
    "dataMode": "SIMULATED",
    "price": { "value": "2.1600", "currency": "USD", "unit": "USD_PER_GPU_HOUR" },
    "sampleSize": 32
  }
}
```

合并规则：

1. `eventId` 去重。
2. `sequence <= currentSequence` 的事件不覆盖当前状态。
3. `sequence > currentSequence + 1` 视为缺口，暂停行情更新状态并重新建立模拟快照。
4. 订阅建立后先取得快照基线，再应用更高序号的事件。
5. Worker 重启或演示服务重连后使用相同会话种子恢复；无法恢复时明确新建会话，不拼接两个种子的序列。

### 9.6 成交与深度

- `simulator.getTrades(...)` 只返回当前会话的模拟成交。
- `simulator.getSupplyDepth(...)` 返回当前场景的模拟挂牌供应分桶与数量。
- `simulator.getOrderBook(...)` 返回由同一序列驱动的模拟买卖两侧；不得与真实订单簿类型复用。
- 客户端以模拟 `capabilities` 判断模块是否存在；能力缺失时 UI 不得独立随机补造。

## 10. 非功能需求

### 10.1 性能

- 已登录或匿名用户进入页面后，1 秒内生成/恢复当前模拟会话并标注模拟时间。
- 常规办公网络下，P75 首次可交互时间目标不超过 2 秒；历史图表不得阻塞页面基础信息。
- 初始模拟快照序列化后目标不超过 150 KB，单次历史序列不超过 500 KB。
- 图表在模拟增量更新时避免整棵页面重渲染；连续 30 分钟运行无明显内存持续增长。
- 页面不可见时暂停图表动画和高频状态合并；恢复后通过当前模拟会话快照校准。
- 模拟事件高频时按显示帧批量合并，UI 刷新频率默认不超过 4 次/秒，数据层仍保持事件完整性。

### 10.2 可访问性

- 文本和关键控件满足 WCAG 2.1 AA 对比度。
- 所有筛选、标签页、场景控制、重试和全屏操作支持键盘与可见焦点。
- 状态不能只靠颜色表达；图标、文字和时间必须同步提供。
- 图表具有可读标题、单位、时间范围和文本/表格替代摘要。
- 模拟价格变化不抢夺焦点；引擎状态使用非打断式 `aria-live`。
- 页面最底部披露小字在 12px 下仍满足 WCAG 2.1 AA 对比度，并可被读屏按正常文档顺序读取。
- 遵循 `prefers-reduced-motion`，关闭不必要的闪烁、脉冲和图表过渡。

### 10.3 安全与隐私

- 模拟模块不得导入或调用钱包、充值、支付、广告奖励、真实订单、资产、账本、清算和结算请求函数。
- 模拟会话使用独立内存/存储命名空间，键统一以 `compute-market-sim:` 开头；禁止保存真实账号、邮箱或业务 ID。
- 模拟事件和 P3 沙盒请求只接受 `sim_` 命名空间 ID，发现真实业务 ID 立即进入 `BLOCKED` 并拒绝处理。
- 源码和生产构建默认启用 `COMPUTE_MARKET_SIMULATION=true` 并要求线上共享服务；生产构建强制失败关闭，不能以
  `REMOTE_REQUIRED=false` 启用每设备本地降级数据。
- 开关不能由 URL 参数、DevTools LocalStorage 或后端非受信普通响应修改；关闭开关立即停止 Worker/定时器并清理会话。
- 如专用演示服务使用 WebSocket/SSE，必须独立路径、同源/鉴权、限流且不复用真实行情或交易通道。
- 行情分析埋点只记录模式、场景、引擎版本和匿名交互，不采集模拟明细、提示词、钱包余额或订单内容。

### 10.4 兼容性

- 桌面与 Web 共用核心组件和数据层；平台差异通过现有 Platform 抽象处理。
- P0/P1 不要求移动端正式上线，但窄屏不能崩溃；移动发布需单独完成触控与性能验收。
- 模拟适配器与旧页面解耦；关闭功能开关后恢复旧实现，旧实现不得读取模拟缓存。

去重和口径：

- `view` 在一次路由可见会话内只记录一次。
- 相同异常状态在 10 分钟内按模拟会话去重，避免事件风暴污染统计。
- 不上传完整 `instrumentId`、`simulationSessionId`、seed、成交、委托或持仓明细。

成功指标：

- 模拟器初始化成功率 ≥ 99.5%，初始快照生成 P95 ≤ 800 ms。
- 事件正常条件下端到端可见延迟 P95 ≤ 1 秒。
- 模拟页面触发真实行情、钱包、广告奖励、支付、订单、资产或结算请求的次数为 0。
- 缺失值显示为 0、单位混算、底部披露丢失或模拟数据进入真实业务链路的事故为 0。
- 新版本页面崩溃率不高于旧页面，功能开关回滚可在 10 分钟内生效。

## 12. 测试计划

### 12.1 单元测试

- 标的、场景、种子、单位、状态和模拟能力声明运行时解析。

- 模拟事件去重、乱序、缺口、版本不兼容与快照合并。

- 真实业务 ID 拒绝、模拟命名空间和 `tradeEntry=false` 强约束。

### 12.3 契约与集成测试

- 模拟 V2 Schema、会话、种子、场景、时钟和能力契约。
- Worker 初始化失败、事件停滞、空报价、汇率缺失和无效单位。
- 重复、乱序、缺口、Worker 重启、暂停/恢复和会话重置。
- 模拟快照与增量的最终一致性，跨标签页和后台恢复行为。
- 请求拦截断言：模拟模式不调用真实行情、钱包、余额、广告奖励、支付、订单、资产和结算接口。
- P3 模拟账户操作前后，真实钱包/订单/资产快照逐字段保持不变。

### 12.4 端到端与手工验收

- Windows 客户端和 Web 端从算力中心进入、筛选、切换场景、暂停、重置、重试和主题切换。
- 钱包、商品购买、订单、资产、设备和通知主流程回归。
- 全屏进入/退出、窗口缩放、浏览器刷新和深链接恢复。
- 关闭所有高级能力后，页面中不存在成交、盘口、期限结构或模拟操作入口。
- 常规页、长页面滚动、全屏和窄屏均能持续看到页面最底部模拟披露小字。
- 普通生产构建确认默认连接 KOD 共享源、断网进入错误态，且不包含第三方密钥、大屏 Vue 资源或真实业务写调用。

## 13. 发布、监控与回滚

### 13.1 功能开关

- `computeMarketV2`：P0/P1 新行情主开关，关闭后恢复旧 `MarketPricePanel`。
- `computeMarketSimulation`：模拟数据主开关，源码与新构建默认开启；开发/运维可在构建时显式设为
  `COMPUTE_MARKET_SIMULATION=false` 回滚旧页面。
- `computeMarketRealtime`：模拟事件循环开关，关闭后保留静态模拟快照和历史。
- `computeMarketAdvanced`：P2 成交、比较、深度、盘口和运行指标开关。
- `computeMarketFullscreen`：全屏模式开关。
- `computeMarketAgentExplain`：只读智能解释开关。
- `computeMarketSimulationTrading`：P3 沙盒操作开关，仅受控演示构建可启用。
- `tradeEntry` 在模拟模式始终为 `false`；沙盒使用独立的 `sandboxTradeEntry`，两者禁止别名或互相回退。

源码与构建配置的共享行情默认值：

- `COMPUTE_MARKET_SIMULATION_API_BASE=https://kod.kai.com/api/v1`。
- `COMPUTE_MARKET_SIMULATION_ALLOWED_ORIGINS=https://kod.kai.com`；只接受精确 HTTPS Origin。
- `COMPUTE_MARKET_SIMULATION_REMOTE_REQUIRED=true`；服务失败或数据为空时进入错误态，禁止回退为每台设备各自生成的数据。

开发者需要运行本地服务时可在启动命令显式覆盖 `API_BASE=http://localhost:8088/api/v1`、对应 allowlist 与
`REMOTE_REQUIRED=false`；开发运行时允许固定端口的 loopback，但生产运行时始终禁止 loopback 且强制失败关闭。

### 13.2 灰度顺序

1. 开发/测试环境：确定性、一致性、事件恢复、底部披露和真实业务隔离测试全部通过。
2. 本地开发：显式覆盖到 loopback 服务，使用固定种子验证桌面/Web 同一场景表现一致。
3. 共享环境：使用默认 KOD HTTPS 地址、精确 Origin 白名单和 `REMOTE_REQUIRED=true`，验证两台独立设备收到同一服务器快照与成交序列，再观察 24 小时初始化、Schema、内存和渲染性能。
4. P2 各能力逐个开启，核对成交、盘口、K 线、摘要和全屏的一致性。
5. P3 仅在网络负面测试和真实资产前后快照不变通过后启用 `computeMarketSimulationTrading`。
6. 普通生产构建默认开放只读模拟行情，沙盒交易开关始终关闭；是否开放沙盒能力须另行产品确认。

### 13.3 回滚触发

出现以下任一情况立即关闭对应开关：

- 页面崩溃或白屏显著高于基线。
- 快照失败率连续 5 分钟超过 2%，或 Schema 阻断率异常升高。
- 单位、模拟时间、场景或换算错误导致页面内部数据矛盾。
- 模拟事件出现持续乱序、重复计数、序列无法恢复或定时器泄漏。
- 页面底部持续小字丢失、被遮挡或在全屏模式不可见。
- 出现任何真实行情、钱包、广告奖励、支付、订单、资产、清算或结算请求。
- 未满足能力门槛却出现成交、盘口、期限结构或沙盒操作。

回滚路径：

1. 先关闭具体 P2/P3/事件能力开关，降级为静态模拟快照。
2. 如核心页面仍异常，关闭 `computeMarketV2` 恢复旧行情面板。
3. 停止 Worker/定时器并清理 `compute-market-sim:` 命名空间，不触碰其他 KOD 缓存或业务数据。
4. 修复后从本地演示重新开始，禁止直接恢复专用演示构建。

## 14. 实施边界与建议目录

建议前端结构：

```text
src/renderer/packages/compute-market/
├─ api.ts                 # 模拟适配器与旧页面边界
├─ simulator.ts           # 确定性模拟引擎
├─ scenarios.ts           # 预置种子、场景与数值边界
├─ simulationWorker.ts    # 时钟与增量事件循环
├─ simulationStore.ts     # 独立会话和存储命名空间
├─ schemas.ts             # 模拟 V2 运行时 Schema
├─ types.ts               # 规范化模拟领域类型
├─ capabilities.ts        # 模拟能力与真实业务隔离门控
├─ queryKeys.ts           # React Query key 工厂
├─ stream.ts              # 模拟事件、序列与恢复
├─ formatters.ts          # 单位、金额和时间
├─ components/
│  ├─ MarketIntelligencePanel.tsx
│  ├─ MarketFilters.tsx
│  ├─ QuoteSummary.tsx
│  ├─ PriceSeriesChart.tsx
│  ├─ SimulationState.tsx
│  ├─ SupplyDepth.tsx
│  ├─ SimulationDisclosure.tsx
│  └─ MarketDataState.tsx
└─ __tests__/
```

约束：

- 既有 `src/renderer/packages/computeCenter.ts` 可暂时导出旧接口，但 V2 行情领域类型不继续堆入该文件。
- TanStack Query key 统一放在 `['compute', 'market', 'sim', engineVersion, simulationSessionId, ...]` 命名空间。
- UI 只消费规范化模拟数据，不在组件内直接调用随机函数或创建独立行情状态。
- 模拟引擎是价格、成交、盘口、状态、能力和可比组的唯一权威；P3 沙盒只消费其事件。
- 模拟模块不能导入真实钱包、支付、广告奖励、订单、资产、账本、清算和结算 API。
- 外部“大屏”项目仅作为产品、场景与交互参考，不复制 Vue 外壳和不匹配的视觉代码。

## 15. 依赖与阶段门

| 阶段 | 必要依赖 | 不满足时的处理 |
| --- | --- | --- |
| P0 | KOD 主题、确定性种子、模拟主开关、底部披露和隔离测试 | 关闭新页面，继续使用旧页面 |
| P1 | 模拟 V2 契约、统一时钟、可靠序列和场景边界 | 降级静态模拟快照，不运行事件循环 |

| P2 期限结构 | 同可比组至少两个模拟期限 | 隐藏期限结构 |
| P3 沙盒 | 独立模拟账户、撮合、账本、存储与网络负面测试 | `sandboxTradeEntry=false`；`tradeEntry` 始终为 `false` |

## 16. 已确认决策

1. 采用能力融合，不做仓库级直接合并或 iframe。
2. UI 跟随 KOD 客户端现有视觉体系，不保留深蓝赛博大屏主题。
3. P0/P1/P2 使用确定性、可复现的模拟行情；所有可见行情数据均来自同一模拟会话。
4. 模拟性质只在页面最底部持续小字披露，不要求顶部横幅、弹窗或每卡重复徽标。
5. 模拟模式与真实行情、钱包、卡时余额、广告奖励、支付、订单、资产和结算完全隔离。
6. P3 只开放独立模拟沙盒 `sandboxTradeEntry`；真实 `tradeEntry` 始终为 `false`。
7. 源码与普通生产构建默认启用只读模拟行情并连接 KOD 线上共享服务；生产失败时不生成每设备本地替代数据。
8. 全屏行情属于 P2 独立模式，与常规行情页复用组件、会话和底部披露，不复制第二套应用。
9. 线上 `latest/history` HTTP 500 不阻断模拟演示，但模拟模式不得请求这些接口或作为其静默降级。

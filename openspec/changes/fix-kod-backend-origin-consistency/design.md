## Context

开发构建曾把 `NODE_ENV=development` 等同于“使用本机 KOD 后端”，而钱包模块绕过该判断直接使用官网地址。这种按模块分裂 origin 的方式无法跨不同 JWT 签名域共享会话。

## Decisions

1. 增加唯一的 KOD API origin 解析器。`NODE_ENV` 只描述构建环境，不再决定业务后端；`USE_LOCAL_API` 是切换整套 KOD API 的唯一显式开关。
2. 登录、钱包、算力中心及账户操作复用同一解析器。UI 展示的服务主机也来自同一结果，避免界面与实际请求不一致。
3. 官网后端使用 HTTP 200 返回业务信封 `{code: 401}`，因此认证判断同时覆盖 HTTP 状态和业务码。
4. 每个请求保存发出时的 access token。收到未授权时，仅当当前 token 仍等于被拒绝 token 才清理会话，避免慢请求删除刚登录的新会话。

## Risks / Trade-offs

- 开发者如果需要本机后端，必须使用项目的显式本地模式启动命令；普通开发命令将连接官网。
- 自动清理无效令牌会要求用户重新登录一次，但可终止永久错误循环并防止继续携带无效认证信息。

## Verification

- 地址解析 RED/GREEN 测试覆盖普通开发模式与显式本地模式。
- 钱包 RED/GREEN 测试覆盖 HTTP 401、信封 401、普通业务失败及旧请求/新会话竞争。
- 运行登录、钱包、hook、TypeScript、构建和官网只读健康检查。

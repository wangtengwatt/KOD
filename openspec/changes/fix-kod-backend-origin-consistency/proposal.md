## Why

KOD 开发版把邮箱登录发送到本机 `localhost:8080`，钱包与消费记录却固定请求官网 `kod.kai.com`。两个后端使用不同的 JWT 签名，导致本机签发的令牌被官网判定为“token 无效或已过期”，桌面端和共享 renderer 的移动端无法读取官网账户数据。

## What Changes

- 所有 KOD 登录、钱包、资产和算力请求使用同一个后端地址解析规则。
- 开发环境默认连接官网，只有显式启用 `USE_LOCAL_API` 时才整体连接本机后端。
- HTTP 401/403 及 HTTP 200 响应体中的 401/403 都视为登录失效，并安全清除对应旧会话。
- 旧请求返回未授权时不得清除用户已经建立的新会话。
- 增加地址选择、钱包认证失效和并发会话切换回归测试。

## Impact

- 影响共享 renderer 的桌面、Web、iOS 和 Android 构建。
- 不修改官网后端、数据库、充值、扣款、商品、零售站、对话或生图业务规则。
- 已保存的本机旧令牌会在官网明确返回未授权后失效，用户需重新登录一次。

## Context

现有算力中心把大部分界面放在 `src/renderer/routes/compute-center.tsx`，API 放在 `src/renderer/packages/computeCenter.ts`。后端已经保存商品封面、GPU 资源证明和 `compute_audit_log`，但客户端商品审核只渲染文字；通知只覆盖既有业务事件；订单交付表单让卖家直接填写“商定开通时间”，却没有聊天、双方确认或时段冲突证据。

截图中的订单已经是 `COMPLETED`，所以账户顶部冻结卡时为零符合现有后端结算规则。产品缺陷是订单没有展示原冻结、结算和退款投影，而不是应该让完成订单继续冻结。

## Goals / Non-Goals

**Goals:**

- 让管理员在一个审核详情中看到不可变商品版本、全部商品图和关联 GPU 资质。
- 让审核完成后仍可按类型、结果和时间追溯。
- 让订单沟通、双方排期确认、节点占用和资金担保共享同一订单身份。
- 让买卖双方清楚看到当前担保、结算和退款去向。
- 让托管节点长期销售，同时安全处理未来排期和延迟下架。
- 保持共享 renderer 在 Windows、Web、iOS、Android 上行为一致。

**Non-Goals:**

- 接入 APNs/FCM 离线推送、语音/视频聊天或群聊。
- 允许用户编辑/删除聊天消息或发送任意文件。
- 让平台登录、控制或强制断开供应方服务器。
- 修改人民币充值、卡时汇率、平台佣金或现有 Token 套餐代理。
- 把历史完成订单重新冻结或重新结算。

## Decisions

### 1. 以订单为聊天、排期和担保的唯一聚合根

新订单先进入 `PENDING_SCHEDULE`。买卖双方均可提出结构化时间，对方确认时服务端原子检查节点容量并建立时段锁。客户端只呈现返回的提议、锁和状态，不根据聊天文字生成排期。

### 2. 将新增界面拆成聚焦组件

保留现有路由外壳，新增 `components/compute/` 下的审核中心、订单会话和算力托管聚焦组件；新增 `packages/computeMarketplace/` 下的类型、API 和状态投影。旧 `computeCenter.ts` 继续承载兼容接口，避免一次性重构整个算力中心。

### 3. 审核基于不可变版本

审核详情读取后端返回的版本快照和图片列表。材料字段改变后产生新待审版本；旧上架版本在新版本通过前仍按旧内容销售。状态色只由共享映射决定：待审核黄、通过绿、拒绝红、撤回/失效灰、重新提交蓝。

### 4. 聊天只属于订单参与者

订单聊天支持文字和 JPG/PNG/WebP 图片，消息只能追加。系统事件以独立类型渲染且不可伪造。完成/取消后只读；文本长期保留，图片到期后显示“图片已按保留策略清理”。客户端用增量游标短轮询更新未读，并通过平台抽象触发本地通知。

### 5. 资金视图区分账户余额与订单投影

顶部冻结卡时只显示仍被担保的账户汇总；每张订单显示 `originalFrozenCardHours`、`currentlyHeldCardHours`、`settledCardHours`、`refundedCardHours`。资金时间线由服务端订单事件/账本投影提供，客户端不通过状态名称猜测金额。

### 6. 托管下架是延迟完成的状态机

下架申请提交后，关联商品立即停止新接单；节点继续履行已有排期。客户端显示 `requestedAt`、`minimumEffectiveAt`、`lastBlockingOrderEnd` 和 `estimatedOfflineAt`。只有后端报告条件满足时才显示已下架。

## Error Handling and Security

- 401/403 不清理无关零售站设置；聊天或图片越权使用统一不可见错误。
- 写操作使用稳定请求键并禁止客户端自动重试；结果未知时刷新对应订单，不创建第二次提议或下架申请。
- 聊天图片先执行客户端压缩/类型提示，但服务器校验仍为权威。
- 本地通知不包含聊天图片、SSH 地址、公钥、证件号或其他敏感正文，只显示“某订单有新消息”。

## Migration / Rollback

1. 后端先部署新增表和兼容响应字段，旧客户端继续工作。
2. 客户端先上线审核记录和只读资金投影，再启用聊天/排期和托管下架写操作。
3. 旧订单保持原状态映射；缺少新字段时客户端显示历史订单说明，不推断新流程。
4. 回滚客户端不删除后端数据；回滚后端前先关闭新订单入口并保留新增表以供审计。

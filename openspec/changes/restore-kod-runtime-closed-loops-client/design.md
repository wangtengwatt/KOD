## Context

参见 `proposal.md` 和 `docs/superpowers/specs/2026-08-25-kod-runtime-closed-loops-recovery-design.md`。客户端当前已经包含同事行情提交以及广告、邀请和托管组件，主要风险来自生产接线、账户身份生命周期、响应精度和重复入口，而不是重新设计这些功能。

## Goals / Non-Goals

**Goals:**

- 将官网账户数据、行情、广告、邀请和托管恢复为可重复验证的端到端闭环。
- 保持同事行情界面和协议为权威实现，只做连接、部署与经测试证实的必要修复。
- 对账户切换、令牌刷新、异步响应和大整数 ID 建立统一安全边界。
- 交付可运行 Windows 构建和指向验证版本的现有桌面快捷方式。

**Non-Goals:**

- 不重写行情算法、单位或页面风格，不直接接入新的第三方行情源。
- 不修改 KAI/KOD Logo、品牌、无关设置或聊天功能。
- 不修改当前已部署官网前端的结构、布局、文案或绿色白色视觉。
- 不在客户端保存支付、视频生成、行情或广告后台密钥。
- 不删除旧人民币佣金数据。

## Decisions

### Account-owned remote state

认证存储保留稳定 `accountId`，所有远程查询键和异步回调都绑定账户快照。不同账户之间不复用缓存或在刷新后重放旧请求。只有确定的未认证响应才能清空会话，瞬时网络和服务错误保持登录并允许重试。

### Precision-safe contracts

所有跨边界标识符和精确余额先按字符串解码，再由界面格式化。禁止先解码成 JavaScript `number` 再 `String()`，因为该路径已经丢失 64 位精度。

### Colleague market implementation remains authoritative

保留 `b8c6643` 的适配器、模式、刷新频率、来源说明和不可用状态。生产只将 API 基址接到官网代理；如果验证发现实现缺陷，必须先写失败回归测试，再做最小修复。

### Server-driven media and business policy

广告素材、时长、资格、奖励，邀请状态和奖励，托管 SKU、月租与售价均由服务端返回。客户端不通过总余额推算卡时资格，也不自行宣布奖励、租约或收益成功。

### One entry per user intent

邀请只从侧边栏抽屉进入；托管在算力中心“卡时托管”标签中完成选择、确认、状态和退出。旧功能的数据保留，但重复导航与重复文案移除。

## Risks / Trade-offs

- [服务端和客户端合同版本不一致] → 在 API 边界做严格版本/字段校验并显示可重试错误，不静默使用旧数据。
- [账户切换发生在请求进行中] → 捕获所有者快照并在提交 UI 状态前复核。
- [行情服务或 WebSocket 不可用] → 保留同事的明确不可用状态，不伪造远程数据。
- [媒体服务器不支持分段请求] → 用浏览器兼容的 Range 契约测试和真实 Electron 播放验收阻止发布。
- [托管操作重复点击] → 客户端生成并复用请求幂等键，最终状态始终从服务端重取。
- [服务接线误改官网视觉] → 官网前端文件列入保护扫描，并比较部署前后关键页面截图与 KAI Logo 哈希。

## Migration Plan

1. 在隔离分支创建 Git 检查点并验证同事提交祖先关系、保护范围和无密钥差异。
2. 先添加失败测试，再按账户同步、行情、广告、邀请、托管顺序实施和验证。
3. 先部署向后兼容服务端，再发布官网和客户端。
4. 在隔离环境完成写入型闭环，生产只做只读健康检查和已授权账户读取。
5. 构建 Windows 客户端并把现有桌面快捷方式指向最新验证启动链。
6. 回滚时恢复旧客户端/官网镜像，但保留新增账本、邀请、租约和审计数据。

## Why

KOD 客户端已有官网钱包、行情、广告奖励、邀请和托管界面，但生产运行时的数据身份、代理、媒体和业务入口没有形成稳定闭环，导致用户看到不同步、一直加载或重复入口。现在需要在保留同事行情实现和既有资产的前提下恢复这些闭环，并为生产与 Windows 客户端交付建立可执行验收。

## What Changes

- 让官网钱包、卡时分桶和充值历史以服务端账户为唯一事实来源，并按账户隔离缓存、刷新和令牌重放。
- 采用同事的客户端行情提交 `b8c66432632bfa688cb34eccc8e8e4981e7160c3`，接入官网同源只读行情代理并保留原契约、单位和错误状态。
- 恢复服务端管理的 KOD 宣传广告播放、重试、续传和完整观看后每日 10 奖励卡时到账体验。
- 只保留侧边栏“邀请好友”抽屉，合并邮箱邀请、链接复制、状态跟踪和奖励到账展示，移除重复的历史佣金用户入口。
- 完成 KAI 服务器按月租用、自动托管上架、统一价格、收益展示、自动续租和到期退出的简洁流程。
- 在最终验证后构建 Windows 客户端并同步现有桌面快捷启动链。

## Capabilities

### New Capabilities

- `official-wallet-sync-client`: 官网钱包、卡时和充值记录的账户级同步、精度与错误行为。
- `realtime-market-integration-client`: 同事行情客户端在生产同源代理上的加载、刷新与失败行为。
- `rewarded-ad-playback-client`: 后台素材的可播放、可恢复和完成后奖励体验。
- `unified-referral-client`: 单一邀请抽屉、邮箱邀请、状态跟踪和奖励到账体验。
- `card-hour-hosting-client`: KAI 服务器月租、自动上架、收益和续租/退出体验。

### Modified Capabilities

None.

## Impact

影响客户端认证状态、远程请求封装、React Query 查询键、钱包与算力中心 API/类型、充值记录、行情面板、广告播放、邀请抽屉、托管面板、Windows 构建和桌面启动脚本。KAI/KOD 品牌、Logo、无关聊天/设置功能、用户本地资料和服务端密钥不在修改范围。
